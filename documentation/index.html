Backend API for Prafi (Express + Sequelize + PostgreSQL), with realtime notifications over Socket.IO.

Setup (once)

  1. Import this collection and Prafi-Local.postman_environment.json, then select Prafi Local (environment dropdown, top right).
  2. In Prafi Local set loginEmail / loginPassword (Current value) to the superadmin from .env (SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD), then Ctrl+S.
  3. Start the server (npm run dev or npm run build && npm start). baseUrl is http://localhost:4000.

Login and roles

  • Every request uses Bearer {{token}} (set on the collection; requests inherit it). Public requests have No Auth.
  • Auth → Login saves the token to {{token}} (valid 1 hour). To switch role, change loginEmail / loginPassword (or the Login body) and send Login again.
  • The name of each request says who can call it: (All roles) = superadmin, admin and tenant; (superadmin, admin), (admin), (tenant)… = only those roles; (Public) = no login. Any other role gets 403.

Saved variables

Requests save what the next ones need: token, currentUserId, currentRole (Login) · userId, userRole, registeredEmail (Register) · imageId, imagePath (Upload Image) · productId · categoryId · tenantProfileId · notificationId. Each save is printed in the Postman Console.

Example walkthrough

  1. Login as superadmin → Register Admin → Activate / Deactivate User (activates the new admin) → Create Tenant Category.
  2. Register Tenant → set loginEmail = {{registeredEmail}}, loginPassword = {{newUserPassword}} → Login (now tenant) → Upload Image → Create My Tenant → Upload Image again → Create Product.
  3. Login as the admin (admin…@prafi.test / {{newUserPassword}}) → List Notifications → Activate / Deactivate Product → Landing Products shows it.

Notifications and realtime

Every role gets notifications for the events that concern them (see Notifications); activation notifications include the approval with userId and the user. They arrive live over Socket.IO as notification:new (see Realtime (WebSocket) for connecting in Postman and in the frontend).

Realtime (WebSocket)

1 endpoint

Realtime notifications over Socket.IO (same host and port as the API).

Postman collection files cannot contain Socket.IO requests, so create one by hand (once):

  1. New → Socket.IO, URL {{baseUrl}} (the client version: v4).
  2. Headers: Authorization = Bearer {{token}} (or Settings → Handshake auth: { "token": "{{token}}" }).
  3. Events tab: add listeners notification:new, notification:unread-count, session:ended and turn them on.
  4. Connect. Then run requests from this collection in another tab (e.g. create a product as a tenant) and watch the events arrive.
  5. Save it into this collection (Save → Prafi API) so it stays next to the REST requests.

Auth: the same access token as the REST API. A missing/invalid/expired/revoked token or a deactivated user is refused with connect_error (err.message, err.data.code e.g. UNAUTHORIZED, USER_NOT_ACTIVATED).

Events (server → client)

eventpayloadwhen
notification:unread-count{ count }right after connecting, and after mark-read / read-all / delete (syncs every open tab)
notification:new{ notification, unreadCount }a notification is created for this user (same shape as GET /api/notifications items)
session:ended{ reason, message }reason: logged_out (this token logged out), deactivated (account deactivated), token_expired (1 h token expired). The server then disconnects; the frontend should log the user out.

Each user only receives their own events; all tabs/devices of a user receive them.

Frontend (socket.io-client v4)

import { io } from 'socket.io-client';

const socket = io(API_URL, { auth: (cb) => cb({ token: localStorage.getItem('token') }) });
socket.on('notification:unread-count', ({ count }) => setBadge(count));
socket.on('notification:new', ({ notification, unreadCount }) => { addToList(notification); setBadge(unreadCount); toast(notification.name); });
socket.on('session:ended', ({ message }) => { logout(); alert(message); });
socket.on('connect_error', (err) => { if (['UNAUTHORIZED', 'USER_NOT_ACTIVATED'].includes(err.data?.code)) logout(); });
// after logging in again (new token): socket.disconnect().connect();

The request below only checks that the Socket.IO endpoint is reachable (engine.io handshake, no events).
