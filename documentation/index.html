Backend API for Prafi (Express + Sequelize + PostgreSQL), with realtime notifications over Socket.IO and emails (nodemailer).

Setup (once)

  1. Import this collection and Prafi-Local.postman_environment.json, then select Prafi Local (environment dropdown, top right).
  2. In Prafi Local set loginEmail / loginPassword (Current value) to the superadmin from .env (SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD), then Ctrl+S.
  3. Start the server (npm run dev or npm run build && npm start). baseUrl is http://localhost:4000.
  4. Email: set SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASS, MAIL_FROM in .env to send real emails. Set FRONTEND_URL to the frontend's address: the forgot-password email links to <FRONTEND_URL>/reset-password. Without SMTP_HOST (development) emails are printed in the server log and the OTP / activation token is returned in meta.verification and saved as {{otp}} / {{verifyToken}}.

Login and roles

  • Every request uses Bearer {{token}} (set on the collection; requests inherit it). Public requests have No Auth.
  • Auth → Login saves the token to {{token}} (valid 1 hour). To switch role, change loginEmail / loginPassword (or the Login body) and send Login again.
  • The name of each request says who can call it: (All roles) = superadmin, disnakertrans, admin and tenant; (superadmin, disnakertrans, admin), (admin), (tenant)… = only those roles; (Public) = no login. Any other role gets 403.
  • Every account must have a verified email (mailActive: true) and an active approval (approval.isActive: true) to log in and use the API.

Example walkthrough

  1. Login as superadmin → Register Disnakertrans → Verify Email Link (or open the link from the email).
  2. Register Admin → Verify OTP (code from the email, or {{otp}} in development).
  3. Set loginEmail = the disnakertrans email, loginPassword = {{newUserPassword}} → Login → Activate / Deactivate User with userId = the admin's id and userRole = admin.
  4. Login as the admin → Create Tenant Category.
  5. Register Tenant → Verify OTP → Login as the tenant → Upload Image → Create My Tenant → Upload Image again → Create Product.
  6. Login as the admin → List Notifications → Activate / Deactivate Product → Landing Products shows it.

LogsLog

2 endpointsendpoint

Request and error logs of the API (/api/logs, Bearer {{token}}), superadmin only, read-only.

Stored, one row each when the response is sent: every create / update / delete request (POST, PUT, PATCH, DELETE) from a signed-in user (a request with an expired or invalid token too, without a user), and every auth action, also from guests: login (including a wrong email or password), sign-up, OTP, activation link, resend, forgot / reset password, logout, profile changes (GET /api/auth/me, called by every page, is not). Reads and other guests' requests (reviews, bots) are not stored. A row has: method, path, query, statusCode, durationMs, level (info < 400, warn 4xx, error 5xx), who made it (userId, userEmail, userRole; null for guests), authEmail (auth actions: the email that was given, e.g. for a failed login, or the account of the userId sent), ip, userAgent. requestFields (the names of the sent fields, never their values, plus image for an upload) and responseSummary (a safe extract of a successful response: allowlisted keys such as id, name, email, role, isActive, price, stars, also inside user / approval / product / tenant; a list gives { count }; tokens and passwords can never appear). A failed request also has the error the client got (errorCode, errorMessage, errorDetails); a 5xx also keeps the real error's stack trace in errorStack (only in Get Log; the client never sees it).

  • Request bodies are never stored, and secret query values (token, otp, password, code) are saved as ***.
  • Rows older than LOG_RETENTION_DAYS (default 30) are deleted daily.

Realtime (WebSocket)

1 endpoint

Realtime notifications (and, for superadmins, the live API log) over Socket.IO (same host and port as the API).

Postman collection files cannot contain Socket.IO requests, so create one by hand (once):

  1. New → Socket.IO, URL {{baseUrl}} (the client version: v4).
  2. Headers: Authorization = Bearer {{token}} (or Settings → Handshake auth: { "token": "{{token}}" }).
  3. Events tab: add listeners notification:new, notification:unread-count, session:ended (superadmins also log:new) and turn them on.
  4. Connect. Then run requests from this collection in another tab (e.g. create a product as a tenant) and watch the events arrive.
  5. Save it into this collection (Save → Prafi API) so it stays next to the REST requests.

Auth: the same access token as the REST API. A missing/invalid/expired/revoked token or a deactivated user is refused with connect_error (err.message, err.data.code e.g. UNAUTHORIZED, USER_NOT_ACTIVATED).

Events (server → client)

eventpayloadwhen
notification:unread-count{ count }right after connecting, and after mark-read / read-all / delete (syncs every open tab)
notification:new{ notification, unreadCount }a notification is created for this user (same shape as GET /api/notifications items)
session:ended{ reason, message }reason: logged_out (this token logged out), deactivated (account deactivated), token_expired (1 h token expired), password_reset (the password was reset). The server then disconnects; the frontend should log the user out.
log:new{ log }superadmins only: a row was saved to the API log (same shape as GET /api/logs items, without errorStack)

Each user only receives their own events (plus events for their role, e.g. log:new for superadmins); all tabs/devices of a user receive them.

Frontend (socket.io-client v4)

import { io } from 'socket.io-client';

const socket = io(API_URL, { auth: (cb) => cb({ token: localStorage.getItem('token') }) });
socket.on('notification:unread-count', ({ count }) => setBadge(count));
socket.on('notification:new', ({ notification, unreadCount }) => { addToList(notification); setBadge(unreadCount); toast(notification.name); });
socket.on('session:ended', ({ message }) => { logout(); alert(message); });
socket.on('connect_error', (err) => { if (['UNAUTHORIZED', 'USER_NOT_ACTIVATED'].includes(err.data?.code)) logout(); });
// after logging in again (new token): socket.disconnect().connect();
